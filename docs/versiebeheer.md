# Versiebeheer – eigen praktijkbewijs

De repository is op 24 november 2026 met hulp van ChatGPT ingericht. De volgende handelingen zijn bedoeld om zelf uit te voeren en te kunnen uitleggen; dit document is geen bewijs dat ze al zijn uitgevoerd.

## 1. Bestaande pull request beoordelen
Open pull request #1 (feature/reserveringen naar develop). Bekijk Files changed en Commits, controleer de broncode en voeg de wijzigingen pas samen wanneer je akkoord bent. Maak daarna een pull request van develop naar main en controleer ook die.

## 2. Zelf een wijziging beheren
- Maak vanuit de actuele main of develop een nieuwe featurebranch voor een echte wijziging in je website.
- Pas bijvoorbeeld een daadwerkelijk gewenste tekst in het reserveringsformulier aan. Controleer de wijziging op de testwebsite en exporteer de aangepaste snippet.
- Commit de wijziging met een bericht dat beschrijft wat en waarom je iets hebt aangepast.
- Bekijk de diff, open een pull request, controleer de wijziging en merge deze naar de juiste doelbranch.
- Bekijk de commitgeschiedenis en leg uit hoe je een eerdere versie terugvindt. Gebruik indien nodig een revert-commit in plaats van bestaande geschiedenis te wissen.

## 3. Bewijs verzamelen
Maak screenshots van je branch, eigen commit en diff, pull request en merge, en commitgeschiedenis. Noteer wanneer je de handelingen hebt uitgevoerd en wat je hebt gecontroleerd. Leg zelf uit wat branch, commit, pull request en merge betekenen.

Gebruik geen klantgegevens of geheime configuratie in deze openbare repository. Dit is aanvullend bewijs van je huidige vaardigheid, geen gereconstrueerde geschiedenis van eerdere ontwikkelweken.
